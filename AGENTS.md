# AGENTS.md — Argand

Argand — кроссплатформенный редактор и анализатор сигналов с акцентом на **I/Q (комплексные)** сигналы. UX вдохновлён ocenaudio (осциллограмма + спектрограмма + редактирование выделениями), но, в отличие от аудиоредактора, Argand работает еще и с комплексными отсчётами и радиочастотной семантикой.

> Этот файл — контекст проекта для Claude / Claude Code. Держи его в синхроне с кодом: меняется архитектура или инвариант — правится и здесь.

## Что это и для кого
Инструмент для просмотра, навигации, редактирования и спектрального анализа записанных сигналов, включая SDR/РЧ-захваты. Целевой пользователь умеет работать со своими (нестандартными) форматами и нуждается в быстром, лёгком нативном приложении, а не в тяжёлом фреймворке.

## Технологический стек
- **Язык:** Rust (stable), организация — Cargo workspace.
- **GUI:** GPUI (от Zed) + gpui-component (Longbridge). Лицензия фреймворка — Apache-2.0.
- **Рендер:** GPUI (графический бэкенд мигрирует Blade → wgpu). Спектрограмма рисуется как RGBA-текстура (image element), осциллограмма — через paths/quads. Публичного хука «свой шейдер/wgpu-проход в кадр» у GPUI нет — см. «Рендер-шов».
- **DSP:** rustfft / realfft.
- **Конфиг:** serde + TOML.
- **Логи:** tracing.

## Ключевые требования (инварианты)
1. Linux + Windows + macOS.
2. Один бинарник + конфиг; минимум внешних зависимостей. GPUI и gpui-component пинить на фиксированную **git-ревизию** (версия на crates.io отстаёт).
3. Быстрый холодный старт и быстрый **первый кадр** осциллограммы/спектрограммы.
4. Полный набор базовых операций отображения и редактирования в объёме ocenaudio.
5. Отдельное окно детального спектра.
6. (план) Система плагинов: форматы, обработка без визуализации, обработка с визуализацией — через отдельный процесс-воркер. **Сейчас отложено** (см. конец IMPLEMENTATION_PLAN.md).

## Доменные заметки (важно: это не обычное аудио)
- Сигнал бывает **real** или **complex** (I/Q baseband).
- I/Q-отсчёты по соглашению — interleaved `f32`: `I, Q, I, Q, …`.
- Спектр комплексного сигнала **двусторонний**: −Fs/2 … +Fs/2, требует `fftshift`. У вещественного — односторонний 0 … Fs/2.
- Ось частот — в **реальных Гц** через `center_frequency` + `sample_rate` (истинная Fs захвата; может быть мегагерцы — это не аудиочастота, воспроизведение как звук целью не является).
- Осциллограмма I/Q — усредненная (I и Q); плюс режим спектрограмма.
- Правки идут по нижележащему массиву отсчётов; cut/copy/paste держат I и Q вместе.

## Архитектура (Cargo workspace)
- **argand-core** — типы предметной области: `Signal` (real/complex, `sample_rate`, `center_freq`, метаданные), `Selection`, единицы; «выходы для рендера» (view-model): `WaveformEnvelope` (min/max), `SpectrogramTile` (RGBA), списки примитивов. Без GUI и без тяжёлого DSP.
- **argand-dsp** — STFT/спектрограмма, PSD (Welch), оконные функции, построение min/max-пирамиды, ресемплинг-хелперы, сдвиг частоты. Зависит от rustfft. Без GUI.
- **argand-io** — чтение форматов: WAV + трейт `FormatReader` (probe/open/read → ленивый источник отсчётов) + встроенные ридеры. Точка подключения нестандартных форматов (позже — через воркер).
- **argand-edit** — движок правок: сегментный буфер (piece-table) поверх mmap-оригинала + вставленные буферы; стек команд (undo/redo); буфер обмена.
- **argand-app** (bin) — UI на GPUI + gpui-component с поддержкой скинов (план): главное окно (осциллограмма + спектрограмма + курсоры/выделения + скролл + статус), окно детального спектра, транспорт. Владеет всем UI и превращает выходы core в примитивы GPUI **Это и есть единый бинарник.**
- (план) **argand-worker** (bin) — процесс демодуляции: `dlopen` C-ABI библиотек, протокол по stdio. Отложено.
- (план) **argand-abi** — C-ABI контракт и типы протокола. Отложено.

## Рендер-шов (не нарушать)
Типы GPUI **не должны протекать** в `argand-core/-dsp/-io/-edit`. Эти крейты отдают данные (текстуры, огибающие, списки примитивов), а `argand-app` превращает их в `image`/`quad`/`path` GPUI. Цель — заменяемость тулкита: если кастомный GPU-канвас GPUI окажется тесным, запасной путь — egui/eframe + wgpu, без переписывания ядра.

## Производительность (как достигаем требование 3)
- mmap входного файла + ленивый разбор; не грузить весь захват в RAM.
- Осциллограмма: многоуровневая min/max-пирамида (peak-кэш), выбор LOD по зуму.
- Спектрограмма: STFT тайлами, прогрессивно (грубо сразу → уточнение в фоне), загрузка в GPU-текстуру; зум/пан трансформами.
- Правки: сегментный буфер → cut/paste за O(1) даже на многочасовых файлах.
- Тяжёлые вычисления — вне UI-потока (rayon / отдельные потоки); UI не блокируется.

## Сборка и запуск
- (после скаффолда) `cargo run -p argand --locked`; релиз — `cargo build --release --locked`.
- GPUI и gpui-component подключать через `git` с зафиксированной ревизией в `Cargo.toml`.
- Полный граф зависимостей фиксируется в `Cargo.lock`; `vendor/` в git не хранится. Для сборки без сети предварительно выполнить `cargo fetch --locked`, затем использовать `cargo build --frozen`. Локальный `vendor/` создаётся через `./vendor-update.sh sync`.
- `rustfmt` + `clippy` обязательны (`cargo clippy --all-targets`).
- Требуется реальный GPU; на software-рендеринге/в части VM возможна деградация.

## Соглашения
- Ошибки: `thiserror` в библиотеках, `anyhow` в bin; в не-тестовом коде без `unwrap`/`expect` на внешних данных. Паника не должна разворачиваться через FFI (актуально для воркера).
- Конфиг `argand.toml` рядом с бинарником или в платформенной config-папке; читается на старте.
- Единицы и оси — в реальных Гц/секундах; не путать аудио-Fs и истинную Fs захвата.
- Комментарии в коде и сообщения - на английском, общение со мной - на русском.
- Комментарии в коде пиши только тогда, когда из самого кода не очевидо его назначение, будь предельно лаконичен
- В коммитах используй английский язык, никогда не упоминай, что при разработке использовался любой из AI (claude, codex, copilot и т.д.)
